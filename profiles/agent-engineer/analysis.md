# 评估目标

评估一条信息是否值得 AI Agent 工程师在未来 24 小时内花时间看。读者关心的是：能不能改进自己的 agent、harness、评测或工具链。

# 评分标准

- **9–10：必须看。** 主流 coding agent / 协议 / 基准发生实质变化；有原始公告、代码或论文可复核；会明显改变 agent 工程师怎么做系统。
- **7–8：今天该读。** 有明确新事实，对架构、工具、评测或工作流有可解释的影响。
- **5–6：扫一眼。** 有点新意，但影响面窄、细节不足，或需要和其他材料拼在一起才有用。
- **3–4：低优先级。** 常规更新、重复报道、宣传腔，或对工程实践影响不清楚。
- **0–2：噪音。** 传闻、标题党、无法证实的性能声明，或跟 agent 工程无关。

# 来源权威

先看来源，再打分。官方 GitHub Release、公司/实验室/工程博客是第一手，应高于 Reddit、Google News、微信科技媒体转述、HN 羊毛帖。

- **官方一手**（仓库 Release、OpenAI / Anthropic / Cursor 等公司或工程博客）：按事实本身给分，可以给到 7–10。
- **从业者一手**（个人技术博客、实验室随笔）：按材料质量给分，不要因为不是公司公告就压分。
- **二手/传闻**（Google News、量子位/新智元/机器之心/夕小瑶/PaperWeekly 等）：没有可点开的官方一手 URL（公司博客、GitHub Release、官方文档）时，分数封顶 **5.5**，且不应占用新闻栏。有官方一手链接时，按转述质量给分，但仍低于原文。
- **社区**（Reddit、X、HN 讨论、GitHub Trending）：没有官方一手 URL 时按闲聊处理，不要用热度抬到 7+。链接到官方 Release / 博客的讨论可以按讨论质量给中高分。
- 当天已有官方 Release 或工程博客时，5.x「记一笔」的二手稿不要占头条或新闻栏。

# 评估要求

优先看原始公告、仓库、论文或可靠报道。区分已发布事实、演示、预告、公司主张和第三方判断。不要把热度当成重要性。给出 3–5 个具体主题标签，优先用：harness、mcp、eval、memory、orchestration、coding-agent、permissions、observability。
